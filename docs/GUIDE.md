# FunPay BOT v1.60 — руководство

[← На страницу проекта](../README.md) · [Происхождение компонентов](SOURCES.md)

Бот предназначен для управления одним аккаунтом FunPay из одной Telegram-супергруппы с темами. Интерфейс русский. В публичной поставке нет плагинов; встроенные инструменты лотов доступны сразу.

## Установка и первый запуск

### Подготовка Telegram

Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен. Создайте супергруппу, включите темы, добавьте бота администратором. Нужны права отправки сообщений и изображений, управления темами, закрепления и удаления сообщений. Бот должен получать сообщения группы: проверьте Group Privacy в BotFather и права администратора.

Укажите два идентификатора:

| Поле | Значение |
| --- | --- |
| `telegram.group_id` | Отрицательный ID супергруппы с префиксом `-100` |
| `telegram.owner_id` | Положительный Telegram ID владельца |

Число после `t.me/c/` в ссылке на сообщение используется с префиксом `-100`; номер сообщения или темы в конце ссылки не является ID группы. Имя пользователя `@...` не заменяет числовой ID владельца.

### Доступ к FunPay

Войдите в свой аккаунт FunPay в браузере. В инструментах разработчика откройте хранилище cookies сайта `funpay.com` и скопируйте **значение** cookie `golden_key` в `funpay.golden_key`. Не нужно вставлять строку `golden_key=` или весь заголовок Cookie.

User-Agent возьмите из браузера, в котором авторизован аккаунт: в консоли разработчика выполните `navigator.userAgent` и скопируйте результат в `funpay.user_agent`. Обновляйте ключ при его смене или потере авторизации.

### Linux

Установите Python и поддержку `venv`/`pip` средствами своей ОС. В каталоге проекта выполните:

```bash
bash start.sh
```

Для повторного открытия установщика:

```bash
bash install.sh
```

Скрипты создают `.venv`, если окружения ещё нет, и запускают `main.py`. Можно выбрать интерпретатор при создании окружения: `PYTHON_BIN=python3.12 bash start.sh`.

### Windows

Установите Python с Python Launcher. Откройте `start.bat`. При отсутствии окружения скрипт сначала ищет Python 3.12, затем доступный Python 3.11 или новее. Для настройки используйте `install.bat`.

### Прямой запуск

Из подготовленного окружения доступны:

```bash
python main.py
python main.py --install
python main.py --run
python main.py --config /path/to/config.json
```

Точка входа и версия находятся в `main.py`. Проверка пакетов выполняется до проверки доступов. Отсутствие пакета не заставляет повторно вводить готовые ключи. При нехватке зависимостей устанавливаются точные версии из `requirements.txt` и деклараций установленных расширений.

При первой настройке установщик спросит обязательные данные. Шаблон содержит `YOUR-BOT-TOKEN`, `YOUR-GROUP-ID`, `YOUR-OWNER-ID`, `YOUR-GOLDEN-KEY` и `YOUR-USER-AGENT`; замените их собственными значениями. Необязательные прокси оставлены пустыми.

### Обновление

Остановите процесс. Для обычного обновления заменяйте файлы кода, сохраняя свой `config.json`, каталог `data`, настройки и данные расширений, а также `.venv`. Публичный `config.json` — шаблон; он не заменяет рабочие доступы.

Существующее подходящее окружение не пересоздаётся. Пакеты устанавливаются только при отсутствии или несовпадении объявленных версий. Копия FunPayAPI закреплена и не обновляется автоматически до иной ревизии.

## Доступ и команды

Бот принимает управляющий текст от `owner_id` или от имени самой настроенной группы (`sender_chat.id == group_id`). Кнопки проверяют ID владельца. Другие участники не получают административный доступ. В личных сообщениях нет ответов и рабочих команд.

Команды регистрируются только для заданной группы. Основные: `/menu`, `/lots`, `/backup`, `/proxy`, `/golden_key`, `/restart`. Если установлено расширение, ядро добавляет его команду по имени файла, например `/notes`. Встроенной команды `/debug` в чистой поставке нет.

При запуске проверяются профиль и команды Telegram-бота, устанавливается имя **FunPay BOT**, убираются старые описания. Неизменившиеся значения не записываются повторно. Ограничения Telegram на изменение профиля сохраняются как срок следующей разрешённой попытки.

Главное меню содержит состояние «Онлайн / офлайн», автоматизацию, заказы, лоты, финансы и управление расширениями. Офлайн приостанавливает обработку FunPay; Telegram-панель остаётся доступной.

## Конфигурация

Все файлы настроек — JSON. Имена разделов и ключей сохраняются в нижнем регистре. Словари команд, названия заготовок, шаблоны названий товаров и ID являются данными: не меняйте их регистр автоматически.

| Раздел | Назначение |
| --- | --- |
| `general` | Часовой пояс; по умолчанию `Europe/Moscow` |
| `telegram` | Токен, группа, владелец и отдельный прокси Telegram |
| `funpay` | `golden_key`, User-Agent, прокси аккаунта и интервал опроса |
| `plugins` | `enabled: "auto"` для обнаружения `plugins/*.py`; либо имена файлов через запятую |
| `sellerstatus` | Включение `#status`, отметка онлайн и тексты последней активности |
| `autoraise` | Включение и резервный интервал автоподнятия; ожидание площадки имеет приоритет |
| `autowithdraw` | Способ, реквизиты, порог, резерв, сумма и интервал автоматического вывода |
| `finance` | Отключаемый учёт задержки 48 часов, уведомления о доступности, вспомогательный ID лота для получения баланса при необходимости |
| `notifications` | Переключатели отдельных типов уведомлений |
| `ratingrestrictions` | Проверка ограничений аккаунта |
| `statistics` | Необязательная публичная статистика RMTHub и срок её кэша |
| `autogreetings` | Общий текст, пауза, только новые чаты и `lot_greetings` |
| `autoresponse` | Точные команды покупателей и текст уведомления владельцу |
| `confirmationreply` | Ответ после подтверждения выполнения покупателем |
| `confirmreminder` | Напоминание о подтверждении после выполнения |
| `reviewreminder` | Напоминание об отзыве |
| `reviewreply` | Тексты ответов на отзывы по оценкам `1`–`5` |
| `reviewchatreply` | Сообщения покупателю после отзыва и правило изменения отзыва |
| `autoticket` | Включение, час проверки и текст обращения |
| `chattemplates` | Заготовки продавца для кнопок в темах чатов |
| `fulfillment` | Общий текст выполнения заказа и дополнительная строка чека |
| `messages` | Вотермарка сообщений |
| `rates` | Рыночные курсы CoinGecko и частота обновления |
| `weeklyreport` | День недели и час отчёта; понедельник — `0` |
| `logging` | Уровень файлового журнала, максимальный размер и число ротаций |

`admin_ids` не используется: доступ задаётся только через `owner_id` и `group_id`. Отдельного общего конфига демпера нет: расширение передаёт профили и настройки общему обработчику ядра. Настройка задержки средств — переключатель; штатный срок составляет 48 часов.

Прокси Telegram и FunPay независимы. Можно оставить пустую строку либо указать URL вида `http://USER:PASSWORD@HOST:PORT` или поддерживаемый SOCKS-прокси. Меню `/proxy` позволяет менять соответствующий уровень. Меню `/golden_key` меняет ключ аккаунта FunPay.

## Сообщения и шаблоны

При начальной синхронизации старые сообщения не пересылаются в Telegram. Дальше создаются темы покупателей и отображаются новые сообщения, изображения, системные события и сообщения поддержки. Система помечается `🔵`, поддержка — `🆘`, отдельный чат поддержки — `‼️`.

В закрепе чата выводятся «Заготовки продавца:» и кнопки из `chattemplates.items`. Заготовки, ответы покупателю, приветствия, напоминания, ответы на отзывы и вотермарка хранятся в конфиге, а не в коде. Тексты меню и статусов интерфейса находятся в коде.

Нажатие заготовки отправляет её покупателю. Обычные текст и фото в теме чата также уходят на FunPay; бот показывает результат отправки. При неизвестном сетевом результате автоматического повторения нет, чтобы не послать одно сообщение дважды.

### Команды покупателя

`autoresponse.commands` сопоставляет полную команду без учёта регистра. Пример для команды `помощь` уже находится в шаблоне:

```json
{
  "enabled": true,
  "trigger_author": "buyer",
  "response": "Текст ответа покупателю",
  "notify": true
}
```

Команда `#status` обрабатывается отдельно и сообщает последнюю зафиксированную активность продавца. Источник активности в стандартном ответе не указывается. Бот знает только действия, которые увидел во время своей работы.

### Приветствия товара

`autogreetings.lot_greetings` — словарь «название или шаблон названия → текст». В названии `{}` означает изменяемый фрагмент, например количество. Если подходящего товара нет, используется `default_text`. При подключении расширения, которое предоставляет возможность `greetings`, стандартные приветствия уступают ему; обработка отзывов от этого не меняется.

### Переменные

Одинаково поддерживаются `$username` и `{username}`. Неизвестная переменная остаётся в тексте без замены.

| Переменные | Значение |
| --- | --- |
| `username`, `chat_id`, `chat_name`, `message_text`, `command` | Собеседник, чат и исходное сообщение |
| `date`, `time`, `full_time` | Дата `ДД.ММ.ГГГГ`, время `ЧЧ:ММ`, время с секундами |
| `date_text`, `full_date_text` | Дата словами без года / с годом |
| `order_id`, `order_link` | Номер заказа без `#` и ссылка |
| `order_desc`, `order_title`, `order_params` | Описание и параметры заказа |
| `order_desc_and_params`, `order_desc_or_params` | Описание вместе с параметрами / первое непустое |
| `category`, `category_fullname`, `game` | Категория и игра, если они получены из заказа |
| `recipient`, `quantity`, `product` | Получатель и данные товара, переданные обработчиком выполнения |
| `reference`, `receipt_url` | Подтверждение и чек, если их передал обработчик |
| `last_activity` | Последняя замеченная активность продавца |

У события сообщения без заказа могут отсутствовать данные товара. Неизвестные значения не придумываются. Для автотикета дополнительно используются `{clear_orders}` и `{ambiguous_orders}`; также поддерживаются два последовательных `{}` для списков.

## Заказы и состояние

В теме заказов ведутся карточки и хронология. «Выполнено» означает ручную отметку продавца и отправляет общий текст из `fulfillment.text`. Расширение использует тот же текст и добавляет чек или подтверждение через `fulfillment.receipt_text`. Это не равнозначно подтверждению покупки самим покупателем.

Возврат из панели требует отдельного подтверждения. Перед действием проверяется актуальное состояние заказа. Неизвестный результат денежного действия сохраняется и не отправляется повторно автоматически.

После подтверждения или возврата завершённая рабочая карточка удаляется из `state.json`, когда история успешно отражена в Telegram и нет незавершённых действий. Сохраняются финансовая запись, минимальные идентификаторы сообщений и защита от повторной обработки. Поздний возврат добавляется ответом к прежней карточке в Telegram; заказ повторно не запускается.

`data/state.json` также хранит темы, привязку аккаунта и группы, текущие меню, отметки обработанных событий, незавершённые задания, паузы приветствий, финансовый журнал и данные расширений. Очистка выполняется при старте и во время работы. Финансовая история и неопределённые операции не являются временным кэшем и не удаляются только из-за возраста.

### Автотикеты

Внешняя нейросеть для автотикетов не используется. Отбор проверяет данные выполнения и переписку. Признаки вроде «не работает», «не пришло», «ошибка» или неоднозначная ситуация требуют решения владельца. Первый список предназначен для выполненных заказов без претензий, второй — для неоднозначных случаев. Самого отсутствия ключевого слова недостаточно для доказательства выполнения.

Реализован общий сохраняемый интервал не менее 24 часов между попытками отправки тикета. Он действует и при неизвестном сетевом результате; поэтому повторный тикет по тому же заказу в течение 24 часов также не отправляется. Настройте текст и время, затем включите функцию.

## Встроенные инструменты лотов

Откройте главное меню → менеджер лотов → инструменты переноса и очистки. `funpay_bot/lot_tools.py` — модуль ядра. Файл `plugins/lot_tools.py` не нужен.

Для обычных лотов доступны экспорт своих предложений в JSON, импорт поддерживаемых форматов, перенос, удаление и создание серии на основе шаблона. Экспорт может включать изображения; формат и размеры вложений проверяются при загрузке.

Для серии выберите шаблон лота, введите количества через пробел, например `10 25 50 100`, проверьте предварительный план и выберите, оставить ли созданные предложения активными либо сразу деактивировать именно новые лоты. Бот проверяет доступные ограничения категории; окончательное разрешение создания определяет FunPay. Не все произвольные старые выгрузки можно импортировать: файл должен содержать поддерживаемые поля предложения.

Общий обработчик изменения цен поддерживает `common` и `chips` через `LotProfile`. Он получает от расширения список предложений, количества, ограничения и расчёт минимальной цены. В чистой поставке нет товарного поставщика и готового расписания демпера: сам по себе пустой SDK цены не меняет.

## Финансы и отчёты

Финансовый журнал разделяет поступления, известную себестоимость, возвраты и комиссии. Без переданной себестоимости итог прибыли помечается неполным. Из истории аккаунта до запуска бот автоматически не восстанавливает все затраты.

В меню вывода выбираются способ, реквизиты, сумма и остаток. В ручном режиме после предварительного расчёта нужно подтвердить вывод. При включённом автовыводе бот сам выполняет рассчитанную операцию при соблюдении порога и заданного резерва, без отдельного нажатия подтверждения. Автовывод в шаблоне выключен; параметры и режим включаются отдельно.

Расчётные ориентиры в коде: карта/СБП — 3%, минимум 30 ₽; USDT TRC20 — 6%, минимум 150 ₽. Для уведомления используются пороги 1000 ₽ и 2500 ₽ соответственно. Фактические доступность, комиссия и конвертация определяются расчётом FunPay. Порог нужен для учёта минимальной комиссии, а не является обещанием мгновенного вывода.

Задержка 48 часов отсчитывается от подтверждения заказа и отключается в `finance.hold_enabled`. Уведомление о доступных средствах также отключается. Баланс площадки проверяется отдельно: одного истечения времени недостаточно.

В сообщении курсов показываются рыночные значения CoinGecko с округлением до тысячных. Закупочный курс используется в расчётах себестоимости и не выдаётся за рыночный. Кнопка «Обновить» находится на сообщении курсов; при замене сообщения старый закреп и старое сообщение удаляются.

Отчёты и графики строятся по имеющимся данным. RMTHub при включении даёт отдельную публичную оценку по отзывам; она не подменяет финансовый журнал.

## Резервные копии и обслуживание

`/backup` открывает выгрузку и загрузку ZIP. Резервная копия создаётся только по запросу; фонового резервирования нет. Штатный архив включает основной конфиг, `data/state.json` и `plugins/<имя>/config.json`. Код расширений и их произвольные дополнительные файлы в этот формат не входят: сохраняйте их отдельно при переносе установки.

При восстановлении проверяются формат, контрольные суммы, принадлежность боту/аккаунту/группе и сохранение защиты денежных операций. Восстановление применяется с перезапуском. Архив с ключами предназначен для личного хранения.

`/restart` перезапускает процесс бота. Одновременно с одним `state.json` работает только один экземпляр. Журналы находятся в `data/log.log`; расширение дополнительно пишет в `data/plugins/<имя>/log.log`, и его события попадают в общий журнал и терминал.

Ожидаемые ограничения частоты и времени ожидания отображаются как WARNING. Настоящая ошибка выводится в терминале одной короткой строкой «Произошла ошибка при выполнении … (подробнее в журнале)»; подробности и traceback сохраняются в файлах. HTTP 502 и captcha не считаются штатным ожиданием подъёма.

## Свой плагин

### Файл и обнаружение

Расширение — **один Python-файл** `plugins/<name>.py`. Имя: нижний регистр, латинские буквы, цифры и `_`, первая буква — латинская; длина до 24 символов. В папке `plugins/<name>/` размещаются его `config.json`, данные и Markdown-промпты, если они нужны. Дополнительные Python-модули в папке данных не используются.

Обязателен `API_VERSION = 1`. Название задаётся `NAME`. Используйте `FrameworkPlugin` из `unified_sdk`; товарные расширения могут использовать `CommercePlugin`. Файлы в публичной поставке отсутствуют: пример ниже приведён только в документации.

Сохраните как `plugins/notes.py`:

```python
from unified_sdk import FrameworkPlugin

API_VERSION = 1
NAME = "📝 Заметки"
REQUIREMENTS = {}
REQUIRED_IMPORTS = {}


class Plugin(FrameworkPlugin):
    """Хранит заметку владельца в настройках расширения."""

    def __init__(self, ctx):
        """Регистрирует настройки и обработчики общего фреймворка."""
        super().__init__(ctx)
        self.settings = ctx.config_store({"Plugin": {"note": ""}})
        self.runtime.on("start", self.started)
        self.runtime.on("message", self.receive)
        self.runtime.router.on("menu", lambda action, user: self.menu())

    async def started(self):
        """Восстанавливает существующее меню без повторной отправки."""
        await self.menu()

    async def menu(self, *, new_message=False):
        """Показывает главное меню расширения."""
        note = self.settings.data.get("Plugin", "note", fallback="")
        await self.ctx.card(
            "📝 Заметки\n" + (note or "Отправьте заметку в эту тему."),
            [[("Открыть меню", "menu")]],
            new_message=new_message,
            main_menu=True,
        )

    async def receive(self, text, user):
        """Сохраняет введённый владельцем текст в JSON, а не отправляет покупателю."""
        self.settings.data.set("Plugin", "note", text)
        self.settings.save()
        await self.menu()
```

После обнаружения файла появятся тема и команда `/notes`. Включение и выключение выполняются в разделе «Плагины». Команда расширения отправляет новое меню, удаляет прежнее и закрепляет новое. Обычный запуск обновляет существующее меню. Кнопка «Закрыть» добавляется только главному меню; вложенным разделам нужна кнопка вида `< Меню`.

`ctx.card` сам добавляет префикс `<name>:` к callback. Передавайте короткие действия в нижнем регистре (`menu`, `settings:page`), не дописывайте префикс дважды. `ctx.say` пишет в тему расширения. `ctx.send_buyer(event, text, action_id)` отправляет сообщение через общий журнал защиты от повторов.

### Настройки, зависимости и журналы

`ctx.config_store` создаёт `plugins/<name>/config.json`; `ctx.state` — небольшой раздел рабочего состояния. Храните большие базы и историю в собственной папке, а временные записи удаляйте после завершения действия. Тексты ответов покупателю храните в конфигурации или отдельных Markdown-файлах.

Если нужен пакет, объявите точную версию литеральным словарём `REQUIREMENTS = {"package-name": "1.2.3"}` и проверку импорта `REQUIRED_IMPORTS = {"import_name": "package-name"}`. Это только схема: замените пример реальным пакетом. Ядро читает объявления через AST до импорта расширения. Зависимости поставщика не добавляются в основной `requirements.txt`. Конфликт версий останавливает подготовку с понятной ошибкой.

Используйте `ctx.logger.info`, `warning`, `error` или `exception`. Фреймворк направляет события в один файл расширения, общий журнал и терминал. Не создавайте отдельный файл журнала для модели или другого внутреннего компонента.

### Жизненный цикл

`start` подготавливает расширение, `stop` отменяет его задачи, `event` получает события, `tick` вызывается планировщиком. Регистрируйте хуки через `runtime.on`; обычные фоновые задачи — через `runtime.start_worker`. Не создавайте собственный бесконечный цикл опроса основного аккаунта.

При запуске сначала подготавливаются все включённые расширения. Рабочие задачи ждут общего разрешения; после подготовки выводятся строки «Готов к работе». Повторный вызов `start` уже работающего экземпляра не запускает его ещё раз.

Для сетевой подготовки до общего запуска предусмотрен `runtime.start_worker(..., initialization=True)`. Если подготовка завершается в фоне, задайте `DEFER_READY = True` и вызовите `runtime.mark_ready()` только после успешного подключения. После этого подготовительная задача должна выполнить `await runtime.wait_running()` перед рабочим циклом. Обычный обработчик с `DEFER_READY = False` отмечается готовым автоматически. Изменение отдельной настройки не требует повторно объявлять инициализацию всего расширения.

### Товар и поставщик

`CommercePlugin` объединяет общий механизм торговли с двумя адаптерами: `ProductAdapter` разбирает количество и получателя, `ProviderAdapter` отвечает за доступы и работу поставщика. Закупка и её подтверждение реализуются расширением; ядро предоставляет общий учёт, выполнение, состояния и интерфейс. Одного объявления `CommercePlugin` без методов поставщика недостаточно для рабочей выдачи.

Для сообщения о завершении используйте `ctx.fulfilled(event, details={...})`, передав `reference` и/или `receipt_url`. Не отправляйте второй независимый текст выполнения: ядро применяет `fulfillment.text` и добавляет подтверждение. Передача этой информации сама по себе не подтверждает заказ за покупателя.

Расширение передаёт лоты через `LotProfile(owner, category_id, kind, lots, parse_quantity=...)` и расчёт минимальной цены в `ctx.app.lot_dumper.reprice`. В `kind` допустимы `common` и `chips`. Для `chips` требуется полный составной ID предложения. Менеджер лотов общий и открывается из главного меню.
